# Google Search Console — Setup & Ongoing Playbook

Everything on this page is a **one-time setup + a monthly habit**. Until
`NEXT_PUBLIC_GSC_VERIFICATION` is set in `.env`, the site emits no
verification tag — nothing leaks in dev or preview builds.

---

## 1. Create the property

- Go to <https://search.google.com/search-console>
- Add a property. Two options:

| | Domain property | URL-prefix property |
|---|---|---|
| Covers | All subdomains + http/https | Exactly `https://repairkl.com` |
| Verification | DNS TXT record (needs domain registrar access) | HTML tag, URL-prefix |
| Recommendation | **Preferred** — future-proof | Use if you can't touch DNS |

**If you choose the Domain property (DNS):** verification happens at the
registrar, so `NEXT_PUBLIC_GSC_VERIFICATION` is not needed — stop here and
jump to step 3.

**If you choose URL-prefix (HTML tag):** GSC shows a tag like
`<meta name="google-site-verification" content="AbCdEf…">`. Copy **only the
content value** into `.env`:

```
NEXT_PUBLIC_GSC_VERIFICATION="AbCdEf…"
```

Redeploy (or rebuild), then click **Verify** in GSC. The tag is emitted by
`src/app/layout.tsx` via `metadata.verification.google`.

## 2. Confirm the tag (after deploy)

- View source on <https://repairkl.com> and search for
  `google-site-verification` — the content must match GSC exactly.
- Or use the [Google Rich Results / URL inspection](https://search.google.com/search-console) →
  **URL Inspection** → `https://repairkl.com` → "View crawled page" → HTML.

## 3. Submit the sitemap

1. GSC → **Sitemaps** (left menu).
2. Enter `sitemap.xml` (the full URL is `https://repairkl.com/sitemap.xml`).
3. Submit. Status should turn **Success** within a few minutes; "Discovered
   pages" can lag by a day — that's normal.

The sitemap is generated by `src/app/sitemap.ts` (static pages + the 5
service pages + DB-backed slugs where they exist) — nothing to maintain by
hand.

## 4. First indexing push (priority URLs)

For each URL below: **URL Inspection** → paste the URL → **Request Indexing**.
Do ~5 per day; GSC rate-limits aggressively.

Priority order:

1. `https://repairkl.com/` (homepage)
2. `https://repairkl.com/our-services` (service hub)
3. The 5 service pages (`/our-services/fridge-repair`, …)
4. `/about`, `/contact`, `/faq`

Login/panel/onboarding pages are deliberately `noindex` — never request
indexing for those.

## 5. Detecting dropped / failing URLs (monthly, 15 min)

- **Pages → Report** (`Performance`): note the top 10 queries; check none of
  the top pages lost impressions vs last month.
- **Indexing → Pages**: look at "Why pages aren't indexed". Expected entries:
  `Excluded by 'noindex' tag` (auth pages — correct) and redirects. Anything
  under **Crawled – not indexed** or **Soft 404** deserves a look.
- **Sitemaps**: submitted vs discovered count. A big gap (e.g. 18 submitted,
  2 discovered for weeks) usually means internal links to those pages are
  missing — check the pages are linked from the nav/footer.
- **Core Web Vitals** report: the Lighthouse CI budgets in
  `lighthouserc.json` guard this pre-deploy; GSC confirms field data.

## 6. Monthly checklist

- [ ] Sitemap status still Success; URL count matches live pages
- [ ] No new "Soft 404" / "Server error 5xx" entries in Indexing report
- [ ] Top queries reviewed — note any ranking gains on "washing machine
      repair kuala lumpur" style queries
- [ ] Request indexing for any new/changed page (new blog posts, new service
      areas)
- [ ] Check **Links** report: new referring domains (GBP, directories,
      social profiles from Step 13 should start appearing)

## 7. Quick reference

| What | Where |
|---|---|
| Verification token env | `NEXT_PUBLIC_GSC_VERIFICATION` (`.env`) |
| Tag emission | `src/app/layout.tsx` → `metadata.verification.google` |
| Sitemap | `src/app/sitemap.ts` → `/sitemap.xml` |
| Robots | `src/app/robots.ts` (points at the sitemap) |
| Canonicals | `src/lib/seo/pageMeta.ts` (`PAGE_META`) |
